## 构建

在仓库根目录执行。需要支持 C++17 的 Linux 编译器。本仓库在 g++ 13.3.0 上完成过构建。

```bash
make
```

生成根目录可执行文件 `./compiler`。

也可以用 CMake。未指定编译器时，`CMakeLists.txt` 优先选择 `g++`：

```bash
cmake -S . -B build
cmake --build build
```

`build/compiler` 是构建目录里的二进制，构建结束时会再复制一份到根目录 `./compiler`。作业示例使用根目录这份。

## 用法

```bash
echo "int a = 1;" | ./compiler -token > test.token
./compiler -token < test.c > test.token
echo "int main() { int a; a = 1; return a; }" | ./compiler -ast > test.check-ast
./compiler -ast < test.c > test.check-ast
```

程序从标准输入读完整份源程序。一次选择 `-token`、`-ast` 或 `-asm`。`-opt` 只能和 `-asm` 一起用。分析模式无论 `accept` 还是 `reject` 都返回 0。

```bash
echo "int main() { return 1; }" | ./compiler -asm > test.s
./compiler -asm -opt < test.c > test.s
riscv64-linux-gnu-gcc -march=rv64gc -mabi=lp64d -nostdlib -static -no-pie \
  -Wl,-e,_start test.s tests/runtime/libtoyc.s -o test
qemu-riscv64 ./test
```

`-asm` 按现有语法树生成 RV64GC 汇编。整数运算使用 32 位指令。`-opt` 在结果不变的前提下做常量折叠、加乘的简单化简，以及 `return` 之后直线代码的删除。课程评测链接的是自己的 `libtoyc.a`；`tests/runtime/libtoyc.s` 只给本地 QEMU 使用，`putint` 不附加换行。

`-token` 的输出与已经验收的词法阶段相同。`-ast` 在没有错误时只输出 `accept`；有错误时输出 `reject` 和 0-based 行号。它不打印语法树。树在内部建立，语义分析使用它，供后面的代码生成和答辩查看结构。

## 输出

每个 token 单独一行：

```text
<序号>:<类型>:<内容>
```

序号从 0 开始，按 token 出现顺序连续编号，不因为注释、空白或被跳过的非法字符跳号。

类型有两种写法：

- 关键字、运算符、标点写成单引号里的字面量，例如 `'int'`、`'>='`、`'('`、`'&&'`。
- 标识符写 `Ident`。整数常量写 `IntConst`。

内容一律是双引号里的原文，标识符和整数也一样，例如 `1:Ident:"main"`、`3:IntConst:"1"`。

源程序没有需要报告的问题时，stdout 只有 token 流。有问题时先输出：

```text
reject
<0-based行号> <原因>
<0-based行号> <原因>

<恢复后的 token 流>
```

诊断和 token 之间有一个空行。行号按出现顺序排列，源文件第一行是 0。原因文本要能看出是哪个字符；作业说明措辞本身不参与严格比对，但行号后必须有空格。非法字符不进入 token 流，扫描从它的下一个字符继续，不丢弃该行剩下的内容。

## 词法规则

标识符：`[_A-Za-z][_A-Za-z0-9]*`。关键字是标识符全文相等，区分大小写：

`int` `void` `const` `if` `else` `while` `break` `continue` `return`

因此 `integer`、`int0`、`Int`、`if_` 都是 `Ident`。`putint` 和 `getint` 也是 `Ident`。

整数见下一节。词法不检查是否超出 32 位，`IntConst` 的内容保持原文。

运算符和标点按最长匹配：

`+ - * / % = == != < > <= >= && || ! ( ) { } ; ,`

`++`、`+=`、`<<` 都不是一个 token。`a+++b` 是 `a`、`+`、`+`、`+`、`b`。单个 `&` 或 `|` 是非法字符；`&&` 和 `||` 才是运算符。

空白是空格、水平制表符和换行。`\r\n` 与单独的 `\r` 先规范成一个 `\n`，再计算行号。`//` 注释到该行换行前结束，换行本身仍用来增加行号。`/*` 注释到最近的 `*/` 结束，不嵌套；注释可以跨行。先跳过注释，再识别 token，所以注释里的 `$`、`#`、非 ASCII 字符不产生诊断，也不产生 token。`/*/` 不会被当成已经闭合。

不属于上述 token、空白或注释起始的字符都是非法字符，包括 `$ # ? : ~ ^ @`、单个 `&` 或 `|`、引号、反引号、反斜杠、点号、方括号，以及非 ASCII 字符。一个合法 UTF-8 码点记一条诊断；非法 UTF-8 字节单独记一条。

## 负号和 NUMBER 的取舍

课程页面把整数写成：

```text
NUMBER：-?(0|[1-9][0-9]*)
```

若把这条正则按最长匹配直接实现，紧挨着的 `-1` 会成为一个 token：`IntConst:"-1"`。

原题综合样例的源码片段是 `b = +a - -1;`。这里第二个减号和 `1` 之间没有空格。公布的 token 98 到 100 却是：

```text
98:'-':"-"
99:'-':"-"
100:IntConst:"1"
```

样例输出和“整段 `-1` 收成一个 `IntConst`”矛盾。词法分析又不能根据它出现在一元表达式里还是二元减法里来决定（那是语法上下文）。因此两种全局规则只能留一个：

| 规则 | `-1`、`1-2`、`--1` 的 token |
| --- | --- |
| 按正则最长匹配，负号可进入整数 | `IntConst:"-1"`；`IntConst:"1"`、`IntConst:"-2"`；`IntConst:"-1"` 前面再一个 `'-'` 会和 `--1` 的切分纠缠 |
| 按公布样例，负号永远单独成 token | `'-'` + `IntConst:"1"`；`IntConst:"1"`、`'-'`、`IntConst:"2"`；`'-'`、`'-'`、`IntConst:"1"` |

当前实现选择第二行。依据是原题样例 token 98–100，以及平台已经通过的 `l11_unary`、`l18_operator_adjacency`、`l10_mixed`：这些点会覆盖一元负号和相邻运算符。把 `-1` 收成 `IntConst:"-1"` 会改掉样例输出，也可能让已通过的点失败。

无符号数字取最长连续数字，`012`、`00`、`007` 各是一个 `IntConst`，内容保持原文。严格正则 `(0|[1-9][0-9]*)` 匹配不了 `012`；若按最长能匹配的前缀切开，`012` 会变成 `0` 和 `12`。第一次提交用的就是这种切法，平台只有 `l04_numbers` 报“错误输出”，其余 29 个点通过。数字测试是唯一会专门放入前导零、边界值和超长数字、又不一定包含样例里那种 `- -1` 的地方，所以修正落在数字串，不改负号。

这和正则原文并不一致：`012` 不是 `(0|[1-9][0-9]*)` 的一个匹配。公开参考文档也写了不要把 `012` 当成一个 NUMBER。平台结果说明评测没有采用那种切分。另一种做法是把前导零报成 `reject`；`l04_numbers` 排在接受类测试里，非法字符另有 `l21`–`l30`，所以没有加新的诊断。

32 位范围也不在词法阶段拒绝。`2147483648` 和更长的数字仍是一个 `IntConst`，内容是原文。语义约束里的 32 位检查留给后面的阶段。若下一轮仍只失败 `l04_numbers`，再考虑范围诊断。

负号由 `number_minus_follows_sample` 和综合样例锁住。连续数字、前导零、`INT_MAX` 邻值和超长数字由 `number_digit_run` 锁住。

## 变量初始化

语义说明写每个变量声明必须带初始化。文法把 `'int' ID` 后面的 `'=' Expr` 写成可选，示例一包含 `int b;`，作业给出的 `-ast` 命令也使用 `int a;` 且不赋值前的声明。示例一的输出是 `accept`。实现允许 `int` 不初始化，`const int` 仍必须初始化。声明之后可以赋值再使用。不额外做“读取前必须已赋值”的分析。`int main(){ int a; return a; }` 因此也是 `accept`。
