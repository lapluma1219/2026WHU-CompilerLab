- 平台观测：`d0228a9` 在 2026-11-16 22:02:39 的成绩。没有隐藏的 ToyC 源码。

## 为什么比 GCC 慢

能对上的差距有三类。

单块计数循环原来每轮是头上的 `bge` 再加回边的 `j`。GCC 把判断放在底部，一轮只有一条 `blt`/`bne`。以前做过的旋转是在 phi 消除之前复制比较，比较的是自增前的值，回边又绕开了 phi，紧循环更慢，所以当时没有启用。这次在 phi 消除和比较融合之后，寄存器里已经是下一轮的值，只把单块循环的回边改成底部的条件分支。

一长串只含加法的直线代码，GCC 会按 32 位回绕合并系数，再把 2 的幂变成移位。我们逐条 `addw`。构造程序里没有溢出到栈，慢在指令条数，不在 spill。隐藏的 p08 如果真是许多互相独立的活变量，这个合并帮不上。

短路条件里的 `i < n` 在循环体内是真的，`a` 和 `b` 又不随循环变。GCC 把分支提到循环外。我们仍在体内做 `slt`、`beq` 和 `snez`。

除法和取模在这台 QEMU 上已经和 GCC 打平。闭式能打过 GCC，但平台 p01 仍是 GCC 的大约 15%，说明隐藏循环不是 `A*i+B` 这种一次式。

`tests/perf/run_large.py` 把行程放大到运行时间离开启动开销。五次中位。循环还在才拿来比速度。输出和 GCC `-O2 -fwrapv` 一致。

| 程序 | -opt | GCC | 循环还在 | 说明 |
| --- | ---: | ---: | --- | --- |
| 分支两侧之后再次计算 `i*a`，3000 万次 | 82.6 ms | 101.1 ms | 是 | 公共乘在热路径上只有一次，我们更快 |
| 小函数内联后再做 `i % m`，2000 万次 | 58.9 ms | 54.7 ms | 是 | 内联后和 GCC 同级 |
| 同一函数塞进 180 条 `t = t + 0`，400 万次 | 54.8 ms | 13.9 ms | 是 | 语句数超过 160，我们留下 `call`；GCC 删掉加 0 再内联 |
| 尾递归 `acc + (n % step)`，1500 万次 | 42.1 ms | 40.2 ms | 是 | 热路径已经是循环，和 GCC 同级 |
| 八个独立累加，各加 `i % m`，1200 万次 | 52.9 ms | 57.8 ms | 是 | 没有栈访问，我们更快 |
| `i % 2` 选择分支，再加 `i % 3`，2000 万次 | 107.3 ms，改取模后 70.0 ms（69.6–71.6） | 64.1 ms | 是 | GCC 对 `% 2` 用 `andi`，我们原来是 `remw` |

跨块 GVN 只在支配树上下有效：先算到的值能给被它支配的块复用，算完就从栈里丢掉。两个互不支配的块里同一条不变乘法，LICM 会各提一份到循环前，热路径不再各算一次。上面第一行就是这种情况。

内联发生在优化之前，内联后的指令会再走后面的常量、外提和死代码删除，固定四轮，小函数能收干净。语句数按语法树算，`t = t + 0` 也计数，所以 180 条空加会挡住内联。把上限再抬高只会让这种填充变快，真正上百条有效语句的函数，调用开销本身只占几个百分点，这次不改上限。

尾递归 `n == 0` 的热路径已经没有 `call`。`n` 为负时不能收成乘法，原因见上一节。

八个独立累加没有 `lw`/`sw`。调用点才限制在 `s1`–`s11`；循环里没有调用时还可以用 `t3`–`t6` 和 `a0`–`a7`。这份代表程序没有溢出。

多块循环的回边仍是 `j` 加头部的 `bge`。单块才把比较沉到回边。把多块也沉下去之前测过会多一条跳转，这次的 107 ms 对 64 ms 里，能对上的主要是 `% 2` 的 `remw`。改成向零截断的与、算术右移和减法之后，五次是 69.6–71.6 ms，输出仍是 `159999999`。`% 3` 仍是 `remw`，所以还没有和 GCC 的 64.1 ms 重合。

## 系数合并和路径条件

长加法按模 2^32 收成系数。2 的幂用 `slliw`，`2^k±1` 用移位加减，其他系数用 `li` 加 `mulw`。一条加法如果只被后面的线性指令使用，就折进最终结果，不单独占寄存器。指令数没有变少的块保持原样。

比较指令的结果在它自己的真分支上是 1、假分支上是 0。这个常量只替换被该后继支配的使用。`if (5)` 这种普通非零判断不能换成 1，否则后面的 `a <= 5` 会变成 `a <= 1`。没有副作用的不变条件再把循环复制成两份，入口只进其中一份；调用留在原来的边上，零次循环仍从复制后的头部直接出去。流出循环的值在出口补 phi。值如果在出口之后的块里还被用到，这次不复制，避免把 phi 补错。

同一 QEMU、五次中位，对照还没有这两项的编译器。输出都相同。

| 构造程序 | 改之前 | 改之后 | GCC -O2 -fwrapv | 输出 |
| --- | ---: | ---: | ---: | --- |
| 14 次加法的循环，250 万次 | 17.60 ms（17.29–18.78） | 6.65 ms（6.37–6.68） | 5.76 ms | `-5004613` |
| `a && b && i < n`，400 万次 | 11.26 ms（10.46–11.63） | 9.17 ms（7.78–9.48） | 6.13 ms | `1268000000` |
| `i * i`，2000 万次 | 24.02 ms | 17.86 ms | 19.93 ms | `820578176` |

加法链从大约 15 条 `addw` 收到移位和少数加法，已经接近 GCC。GCC 还把 `2*i` 收成每轮加 2，我们这一步没有做。短路仍比 GCC 慢大约 3 ms：GCC 把条件提出去之后循环只剩 `s = s + a`，我们提出比较之后还留着分支。`a == 0` 时不会执行 `putint`，`n == 0` 时累加值保持初值。

尾递归 `n != 0` 再 `n - 1` 没有收成乘法。`n` 为负时会绕过 0 一直减到回绕，和 `n > 0` 的行程不一样。代表程序就是这种判断，收成 `n * step` 会算错。

## 这次启用和没有启用的

启用：单块循环的底部条件分支，见 `sink_loop_branch`。2000 万次 `s = s + i*i`，对照改之前的 `d0228a9`：

| | 五次毫秒 | 中位 | 输出 |
| --- | --- | ---: | --- |
| 改之前 | 23.67–26.0 | 24.2 | `820578176` |
| 改之后 | 18.23–21.61 | 18.85 | `820578176` |

循环从 `mulw`、`addw`、`addiw`、`j` 再加头上的 `bge`，变成四条并且用 `blt` 回到自己。同一输入的除法循环中位 25.1 ms 对 25.05 ms，尾递归 4.6 ms 对 4.43 ms，输出都相同。多块循环不改，避免再补一条跳转。

没有启用：

- 魔数除法。GCC `-O2` 对 `/3` 仍用 `divw`，本地除法循环和 GCC 打平，换成乘法没有更快的测量。
- 早先那种复制自增前比较的旋转。比较的是自增前的值，回边又绕开 phi，紧循环更慢。
- 把 `n != 0; n = n - 1` 收成乘法。负数起点不会在 0 停住。
