# 第三阶段性能对照

这份记录只使用三类材料，三者没有混写：

- 平台观测：`d0228a9` 在 2026-11-16 22:02:39 的成绩。没有隐藏的 ToyC 源码。
- 公开材料：作业说明和 <https://lightsmilew.github.io/compiler-principles/docs/labs/part4-codegen>。两边都没有给出 10 组性能测试的源码，只有“性能样例使用 `-asm -opt`，用 GCC `-O2` 的运行时间做基准”。
- 自己构造的代表程序：`tests/perf/run_matrix.py`。名字按公开类别起，输入来自 `getint`，避免把循环上界折成常数。C 对照使用 `riscv64-linux-gnu-gcc -O2 -fwrapv`，有符号溢出按 32 位回绕，和 ToyC 一致。另编了一份不带 `-fwrapv` 的 GCC，用来看它会不会靠 C 的未定义行为把循环删掉。评测用的 GCC 命令行不在公开说明里，所以那一份只作对照，不当成平台基准。

时间是同一台机器上的 `qemu-riscv64-static`，不是真机周期。每个数至少重复 3 次，下面写中位数和范围。进程启动大约 1.5–2.8 ms，短于这个量级的差不当成优化收益。

命令：

```bash
python3 tests/perf/run_matrix.py ./compiler
```

汇编和计时落在 `tests/perf/out/`，该目录是生成物。下面的循环体和输出是同一次运行里读到的。

| 构造程序 | -opt 中位 | 无优化中位 | GCC -fwrapv 中位 | 输出是否相同 | 循环体 |
| --- | ---: | ---: | ---: | --- | --- |
| 死代码 + `a*i+b` | 2.4 ms | 36 ms | 6.9 ms | 相同 `1642338432` | 我们收成乘法；GCC 仍是 5 条指令的循环 |

| 跨块 `a*b+k` | 2.2 ms | 23 ms | 3.7 ms | 相同 | 两边都把公共式提出去了 |
| 嵌套不变量 | 2.1 ms | 22 ms | 2.4 ms | 相同 | 内层被收掉，剩下的时间和启动开销混在一起 |

## 为什么比 GCC 慢

能对上的差距有三类。

单块计数循环原来每轮是头上的 `bge` 再加回边的 `j`。GCC 把判断放在底部，一轮只有一条 `blt`/`bne`。以前做过的旋转是在 phi 消除之前复制比较，比较的是自增前的值，回边又绕开了 phi，紧循环更慢，所以当时没有启用。这次在 phi 消除和比较融合之后，寄存器里已经是下一轮的值，只把单块循环的回边改成底部的条件分支。

一长串只含加法的直线代码，GCC 会按 32 位回绕合并系数，再把 2 的幂变成移位。我们逐条 `addw`。构造程序里没有溢出到栈，慢在指令条数，不在 spill。隐藏的 p08 如果真是许多互相独立的活变量，这个合并帮不上。

短路条件里的 `i < n` 在循环体内是真的，`a` 和 `b` 又不随循环变。GCC 把分支提到循环外。我们仍在体内做 `slt`、`beq` 和 `snez`。

除法和取模在这台 QEMU 上已经和 GCC 打平。闭式能打过 GCC，但平台 p01 仍是 GCC 的大约 15%，说明隐藏循环不是 `A*i+B` 这种一次式。

## 这次启用和没有启用的

启用：单块循环的底部条件分支，见 `sink_loop_branch`。2000 万次 `s = s + i*i`，对照改之前的 `d0228a9`：

| | 五次毫秒 | 中位 | 输出 |
| --- | --- | ---: | --- |
| 改之前 | 23.67–26.0 | 24.2 | `820578176` |
| 改之后 | 18.23–21.61 | 18.85 | `820578176` |

循环从 `mulw`、`addw`、`addiw`、`j` 再加头上的 `bge`，变成四条并且用 `blt` 回到自己。同一输入的除法循环中位 25.1 ms 对 25.05 ms，尾递归 4.6 ms 对 4.43 ms，输出都相同。多块循环不改，避免再补一条跳转。

没有启用：

- 魔数除法。GCC `-O2` 对 `/3` 仍用 `divw`，本地除法循环和 GCC 打平。
- 把长加法链收成移位。构造程序上能少很多指令，但隐藏样例是否是这种链不知道，而且改写范围大。
- 把循环条件在体内折成常量再外提短路分支。构造程序上 GCC 因此只剩 3 条指令，我们还没做。
- 早先那种复制自增前比较的旋转。
